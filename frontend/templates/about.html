Engineering Specification

StrongHold is a production-grade, non-custodial Bitcoin optimization protocol. Built on open-source Bitcoin infrastructure, the system enforces financial accountability and establishes collateral lending frameworks through cryptographic multisignature contracts, verifiable clinical milestones, and deferred merchant spend pools.

🔗 Bitcoin Layer (L1)

  • bitcoinjs-lib: Multisig script building & transaction crafting
  • ecpair + tiny-secp256k1: ECDSA signing & key management
  • Mempool.space API: Transaction broadcast & confirmation tracking
  • P2WSH: 2-of-3 witness script escrow contracts

⚡ Lightning Network

  • Alby WebLN API: In-browser Lightning payments & invoice handling
  • LNbits: Self-hosted or community Lightning node gateway
  • Micro-payments: Instant survey compensation at scale

🗄️ Backend & Database

  • Node.js + Express: RESTful API server & middleware
  • Supabase (PostgreSQL): User accounts, vault state, oracle logs
  • JWT Sessions: Stateless authentication tokens

🎨 Frontend & UX

  • Vanilla JavaScript: No framework overhead, Web Crypto API
  • Responsive Grid: Mobile-first dark theme dashboard
  • localStorage: Session persistence & credentials caching

1. The Cryptographic Rules Underlying the App

StrongHold relies on native Bitcoin logic to secure capital without central custodians or third-party trusted entities:

🔐 2-of-3 Multisig Escrows

Funds are locked in a unique Pay-to-Script-Hash (P2SH) address compiled from three keys:

  • Recipient Key (student, patient in recovery)
  • Counterparty Key (survey donor, sponsor/lender)
  • StrongHold Server Key (automated oracle arbitrator)

At least two out of three keys must sign to spend the locked collateral.

⏳ Time-Locks (CLTV)

Using OP_CHECKLOCKTIMEVERIFY, script conditions are written directly into transaction outputs. This ensures that regardless of signature combinations, locked Bitcoin cannot move on-chain until a specific block height or UNIX timestamp is reached.

⚡ Hashed Timelock Contracts (HTLCs)

Leveraged for Lightning Network payments. HTLCs secure payments by requiring the recipient to produce a cryptographic preimage of a hash within a designated timeline to claim the micro-payout.

2. Recipient Loan Services & Rule Enforcement

💵 Stablecoin & Mobile Money Lending

Recipients receive immediate spending liquidity (stablecoins or local mobile money loans like M-Pesa) backed entirely by their locked Bitcoin. This safeguards the borrower from being forced to liquidate their appreciating digital assets for short-term emergency costs.

⚖️ Liquidation & Recovery Protocols

If a borrower defaults or fails clinical milestones (e.g. failing a drug screen), the StrongHold server oracle detects the breach. The server co-signs with the Lender/Donor Key to execute a liquidation refund, transferring the collateral to cover outstanding debt. If complied with, the server co-signs with the Recipient Key to unlock the asset.

🔌 Server-Client Communication

  • On-Chain/Off-Chain: Wallet creation and key pair derivation occur locally in the client browser.
  • Webhooks & APIs: Server monitors the ledger for transaction confirmations while linking to clinical databases.
  • Handshake: Server generates its signature fraction and transmits it to finalize transaction construction.

💡 Deepening the Technical Foundation: Simplicity Smart Contracts

To scale beyond classic multisig and locktime constraints, we are tracking developments like Verifiable Smart Contracts with Simplicity at Bitcoin 2026. Simplicity offers a formal verification framework that allows developers to write robust, mathematically provable smart contracts directly on Bitcoin script layers, eliminating the security exploits of Turing-complete virtual machines like EVM.
